Plane 4 · the verdict

Judging by recomputation, not arbitration.

Deciding who won a hand of poker is easy — the rules are mechanical. The hard part is that in a dispute the chain holds only what the parties submitted, and every validator must independently derive byte-identical results from that input. Any divergence is not a bug; it is a consensus fork that halts the chain. This page is how that constraint is satisfied.

Why determinism is the whole problem

The "state transition function" here is an entire poker rules engine plus elliptic-curve verification — orders of magnitude more complex than a transfer or a delegation. The chosen approach (ADR-003, "Scheme A") is to implement the engine once in C++, expose it through a pure C ABI, and link it into the validator binary via cgo, so every validator executes the identical implementation.

Two integration decisions guard the boundary:

  • The Go side is decoupled at a []byte → []byte interface. Without the cgo_adjudicator build tag the adjudicator is nil and AdjudicateSession returns ErrAdjudicationUnavailable — a misconfigured pure-Go node fails loudly instead of silently returning a default verdict.
  • Every C ABI entry point is wrapped in a catch-all. A C++ exception unwinding into Go is undefined behaviour, and a crash inside consensus halts the chain; exceptions are mapped to deterministic status codes at the boundary.

The three-layer determinism guard

Layer 1 — runtime sentinel

The invariant: the adjudication path must never consume cryptographic randomness. Shuffle proving needs an RNG; shuffle verifying does not — but both live in the same translation unit, so a compile-time split is not available. Instead a thread_local armed/disarmed flag with an RAII scope guard (DeterministicGuardScope, nestable) is armed on entry to adjudication, and every actual entropy source — generate_random_with_openssl<T>(), RandomKey(), generateRandomIV() — calls checkDeterministicGuard() and throws if armed. Non-reproducible output is converted from a silent consensus hazard into a loud, deterministic failure.

Layer 2 — structural isolation

The poker_adjudicator target links bitpoker_gamecore only. Non-deterministic dependencies are not merely discouraged; they are unlinkable. A contributor cannot pull boost::asio or the wallet layer into the consensus path with an #include — the link fails at build time, on every machine, before review even sees it.

Layer 3 — cross-architecture differential CI

"Byte-identical" is not a claim that survives code review. A frozen corpus of eight real DisputeAdjudicationRequest payloads covering every verdict path is replayed in CI on both ubuntu-24.04 (x86_64) and ubuntu-24.04-arm (arm64); each run emits <name> <abi-status> <sha256(result-bytes)> and the workflow diffs the two architectures against a committed golden digest. Any divergence fails the gate. In practice this has held across compiler and optimisation changes — gcc-15 -O0 debug rebuilds reproduce goldens generated by gcc-16 -O2.

The adjudication pipeline

adjudication_engine — six stages, short-circuit priority parse request → preflight: context / key / signature validation → shuffle chain reconstruction + NIZK verification → betting replay through the live state machine → decrypt & rank → allocate pot / assign fault → serialise result

Preflight validates both session public keys, checks secret_key · G == authoritative public key point, and attributes every message in the history to a seat by signature. Note the subtlety: an inconsistent secret does not fail the request — it marks secret_valid = false, which the verdict stage treats as a forfeit. The request always produces a verdict if it parses; only malformed input fails.

Shuffle verification extracts the two shuffles, forms the combined key by point addition (order-independent), and verifies before → after stepwise, returning Verified / Incomplete / BadShuffle.

Betting replay runs the recorded actions through the same state machine the live game uses, with seat attribution taken from preflight signatures — so turn-order violations are caught by the engine's own OutOfTurn check, not by a parallel rule.

Decrypt and rank is possible because the adjudicator holds both session secret keys, so it decrypts the verified stack directly without any submitted per-card keys — by the RNG-free route described on the crypto page.

Allocation ignores the claimed dispute reason entirely. The engine does not trust the requester's stated grievance; it derives the outcome from evidence, in short-circuit priority order:

  1. Hard cryptographic violation (bad shuffle)
  2. Hard logic violation (illegal action)
  3. Fold already resolved the hand
  4. Requires decrypt-and-compare — including forfeit for missing/invalid secrets, and refund when the hand never dealt out

Pot allocation first returns uncalled excess bets, then splits the matched portion by the comparison result; an odd chip on a split goes to the big-blind seat, matching the live settlement path exactly.

Verdicts, faults and fees

verdict FIRST_PLAYER_WINS · SECOND_PLAYER_WINS · SPLIT · REFUND
result code SHOWDOWN · FORFEIT_NO_SUBMISSION · FORFEIT_INVALID_SECRET · VIOLATION_BAD_SHUFFLE · VIOLATION_ILLEGAL_ACTION · BOTH_FORFEIT · REFUND_UNDEALT
fault NONE · FIRST · SECOND · BOTH

The dispute fee (ADR-004) is charged only when fault is single-sided — from the at-fault side's payout, routed to the standard Cosmos fee collector, so it reaches validators through the same pipe as gas. No fee when fault is NONE (a normal showdown or fold is not misconduct) or BOTH (each side simply gets its stake back). Pot conservation is unaffected: the fee changes the split, not the total.

The honest assessment recorded in ADR-004: the default dispute_fee_bps has no quantitative justification. Too high and an honest player with the bad luck of a cheating opponent is taxed for it; too low and it fails to deter. It is a governance parameter awaiting real data.

Who triggers adjudication

Either participant may trigger it at any time. After dispute_timeout_blocks, anyone may — a permissionless crank. This closes the fund-lock risk without requiring the at-fault party's cooperation.

"Anyone may" only closes it if someone actually does, so the relay daemon does: it sweeps the sessions it answered and sends the verdict request once the dispute deadline passes, and likewise voids an ACTIVE session that ran out its abandoned-session deadline. The incentive is structural rather than altruistic — a session releases the relay capacity slot it booked only when it terminates, so an escrow left locked is a seat the relay can never sell again.

"May" is not "does", and that gap is a client obligation. Nothing on the chain reveals a secret or asks for a verdict on a player's behalf, so every client must offer both — reveal first, then adjudicate, in that order, because a seat whose secret was never disclosed is scored as having forfeited the whole escrow. The per-hand secret lives in the game core's memory, and the hands that end up disputed are precisely the ones where that memory is gone with the crashed client — so the secret is written down when the intent is opened and deleted once it is spent.

Automatic adjudication in EndBlock was deliberately not built. If a validator without the cgo engine participated in an EndBlock that calls it, the result would diverge and halt the chain. The permissionless crank achieves the same liveness property — the winner and any watcher are both motivated to call it — at far lower risk.

Versioning and upgrades

An EngineVersion string (currently 0.8.0) is stamped into every verdict by the C ABI layer. Any change to adjudication behaviour must bump it, and is treated as consensus-relevant — requiring a coordinated chain upgrade, not a client release. The engine's gas metering changed in 0.8.0 (signature and shuffle-proof verification moved from "runs in cgo for free" to charged-by-deterministic- counter), which is exactly the kind of change that version exists to mark.

And the standing gate: a pure-Go build of pokerchaind must never reach a validator fleet — it returns ErrAdjudicationUnavailable for every MsgAdjudicateSession, which would lock every disputed escrow forever. Three guards enforce this (no Makefile target produces a pure node; a hand-built pure binary refuses to start; the packager reads go version -m tags and the ArchiveHash stamp).
